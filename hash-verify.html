    How Hash & Verify works

    First: what is a hash?

    A hash is a short digital fingerprint made from text or a file. If even one character or file byte changes, the fingerprint will almost certainly change too. Making the fingerprint is easy; using it to recover the original text or file is not practical. So a hash is not a way to hide or encrypt your message.

    For example, the word hello always produces the same SHA-256 hash. Change it to Hello with a capital H and the hash becomes completely different.

    Hash text or file

    Choose Text to type or paste words, or choose File to select a file from your device. Pick SHA-256, SHA-384, or SHA-512, then click Generate Hash. The result is a hexadecimal string: a sequence of numbers and letters from 0 to f. SHA-256 is a good default for ordinary integrity checks; the three options are different digest lengths of the SHA-2 family.

    Copy Hash copies the result. Clear removes the text, selected file, and verification value.

    Verify hash

    Use this when you already have a trusted hash for a file or text and want to check your copy. Select the same input and algorithm used for that trusted hash, paste it into Expected hash, and click Verify Hash. “Match” means the input produces that exact hash; “No match” means it does not. A match only helps if the expected hash came from a source you trust.

    Batch hash text

    Put one text value on each line and click Run Batch. Empty lines are skipped, and up to 100 non-empty lines are hashed separately using the selected algorithm. Each result shows its original line number, text, algorithm, and hash. Copy JSON or Download JSON gives you the results as structured data you can save or use elsewhere.

    Privacy and safety

    Hashing happens in your browser. Files are read locally; this tool does not upload or save your input. SHA hashes are not encryption and should not be used to store passwords. For sensitive files, compare hashes over a trusted channel.
